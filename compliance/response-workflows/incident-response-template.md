# Incident Response Template — SOC Workflow

## Overview

This document defines a structured incident response workflow based on events observed within the Blue Team Detection Lab.

It translates detection alerts into actionable response steps aligned with SOC operations and cybersecurity frameworks.

---

## Incident Classification

| Severity | Description | Example |
|----------|------------|--------|
| Low | Suspicious activity with low confidence | Single scan event |
| Medium | Confirmed suspicious behavior | Repeated login attempts |
| High | Active attack or compromise attempt | SSH brute-force |
| Critical | Confirmed system compromise | Unauthorized access |

---

## Detection Trigger

**Example Scenario:** SSH Brute-Force Attack

### Trigger Sources
- Suricata alert (network anomaly)
- Cowrie failed login attempts
- Wazuh correlated alert

---

## Incident Response Workflow

### 1. Detection

- Alert generated by **Suricata / Wazuh**
- Initial signal identified (e.g., SSH brute-force)

---

### 2. Validation

- Confirm activity using:
  - Cowrie session logs
  - Suricata `eve.json`
  - Wazuh alerts
- Match:
  - Source IP
  - Timestamp
  - Attack pattern

---

### 3. Classification

- Identify attack type:
  - Brute-force
  - Credential abuse
  - Reconnaissance
- Map to:
  - MITRE ATT&CK technique
  - Threat category

---

### 4. Analysis

- Review attacker behavior:
  - Login attempts
  - Target service
  - Frequency of requests
- Determine intent:
  - Scanning vs active exploitation

---

### 5. Containment

- Options:
  - Block source IP (firewall rule)
  - Continue monitoring (honeypot)
  - Isolate affected system (if applicable)

---

### 6. Documentation

- Record:
  - Source IP
  - Timestamp
  - Detection source
  - Attack technique
- Store logs and evidence

---

### 7. Response Improvement

- Update detection rules if needed:
  - Suricata signatures
  - Wazuh rules
- Refine alert thresholds
- Improve correlation logic

## Key Insight

Effective incident response is not just about detecting threats;
it is about **validating, classifying, and acting on them quickly and consistently**.

This workflow demonstrates how raw alerts are transformed into structured security operations.
